# 固收基金跟踪系统设计

## 背景

现有 `fof-tracker` 是本地静态前端项目，用于跟踪公募 FOF 的申报、受理、获批、发行、成立以及公司竞争格局。新项目需要克隆该工作台能力，但分析对象改为固收基金，并作为同级独立项目存在。

新项目目录为 `fixed-income-fund-tracker`。已有同级目录 `fixed` 是固收资料知识库，不作为本次目标目录，也不覆盖。

## 目标

创建一个可本地运行的固收基金跟踪系统，保留原 FOF 项目的工作台体验和数据构建链路，但完成业务语义迁移：

- 对象从 FOF 改为固收基金。
- 分类从 `FOF类型` 改为 `固收类型`。
- 文件、脚本、配置、浏览器全局变量、README、命令入口统一改为固收基金命名。
- 页面文案和核心分析模块改为固收基金发行与竞争格局。
- 原项目不被修改或覆盖。

## 固收分类

第一版内置以下固收类型：

- 短债基金
- 中长期纯债基金
- 混合债券型基金
- 被动指数债基
- 同业存单指数基金
- 债券ETF
- 其他固收

分类优先使用输入数据中的 `固收类型` 字段；如果缺失，则按基金名称和产品类型关键词推断。推断规则聚焦可解释性，无法稳定识别时归入 `其他固收`。

## 数据流

新项目保留原来的构建方式：

1. 优先读取项目根目录的业务 Excel。
2. 自动合并申报、受理、获批、发行、成立阶段数据。
3. 输出前端 snapshot JSON、JS 和明细 CSV。
4. 前端优先读取 JS snapshot，失败时读取 JSON。

新文件命名：

- `config/fixed_income_fund_tracker_config.json`
- `data/fixed_income_fund_stage_source_template.csv`
- `data/fixed_income_fund_soft_signal_template.csv`
- `data/fixed_income_fund_tracker_snapshot.json`
- `data/fixed_income_fund_tracker_snapshot.js`
- `data/fixed_income_fund_tracker_detail.csv`
- `scripts/build_fixed_income_fund_tracker_snapshot.py`

## 前端改造

页面结构沿用现有工作台：

- 首页总览
- 流程跟踪
- 公司格局
- 存量与追赶
- 托管行渠道
- 智能简报
- 产品详情

文案改为固收基金语境。全局切片改为：

- 全部
- 短债
- 中长期纯债
- 混合债
- 指数债基
- 同业存单
- 华夏在途

原 FOF 的养老、ETF-FOF、多资产持有期矩阵逻辑替换为固收赛道覆盖视角。保留“华夏 vs 头部机构”的对标方向，但描述改为固收产品线缺口、发行节奏和存量规模差距。

## 命令入口

新项目提供三个可双击入口：

- `一键更新固收基金数据.command`
- `一键打开固收基金跟踪.command`
- `一键全流程.command`

入口脚本以当前项目目录为根目录运行，不依赖原 `fof-tracker` 路径。

## 验证

完成后至少验证：

- 新目录存在且不覆盖 `fixed`。
- 原项目 git 状态不因复制动作产生业务文件回退。
- 构建脚本可通过 Python 语法检查。
- 如果依赖齐全，运行一次 snapshot 构建。
- 启动本地静态服务并确认页面入口可访问。

## 非目标

- 不重新设计 UI 视觉系统。
- 不接入新的外部数据源。
- 不删除或重写原 FOF 项目。
- 不保证第一版固收分类完全覆盖所有历史产品名称变体；无法识别的产品进入 `其他固收`，后续根据真实数据补规则。
